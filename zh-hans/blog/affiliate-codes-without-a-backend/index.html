没有后端的独立 App 怎么做联盟代码

每个合作伙伴一个隐藏的 App 内购买项目，账就交给商店来记。作者：Thomas Willheim · 2026 年 11 月 20 日

大家好。HonorFit 是一款用俯卧撑赚屏幕使用时间的 App 屏蔽工具，采诚信制。它没有账号，也没有服务器。你的数据留在手机上，因为它根本没有别的地方可去。

后来有位创作者问我有没有联盟行销计划。我也想做：创作者拿到一组代码，他们的粉丝买终身版 Pro 打八折，创作者则从每笔销售拿到我收入的 50%。但我看过的每一种联盟行销做法，都默认你有一个后端来保存代码、追踪点击、把购买对应到合作伙伴。我不想为了这件事专门做一个后端，更不想为此打破“什么都不会离开你的手机”这个原则。

所以我改用下面这个做法。iPhone 和 Android 都能用，内容只有付费墙的一个小改动，加上我笔电上的一支脚本。

为什么不用商店自己的优惠代码？

Apple 有优惠代码（offer code），但 Google Play 的一次性产品优惠代码只能把商品免费送出去，没有“打八折”这种选项。我想要一组在两个商店都一样好用的代码，所以商店代码就出局了。

而且就算能打折，还有第二个问题：我每个月都得知道每笔销售是来自谁的代码，才能付钱给大家。

诀窍：每个合作伙伴都有自己的商品

HonorFit 本来就把终身版 Pro 当成一次性购买项目 honorfit_pro_lifetime 在卖，价格 19.99 美元。每个合作伙伴都会拿到这个商品的一份复本，ID 里带着他们的代码，价格设为 15.99 美元：

honorfit_pro_lifetime            $19.99   （所有人看到的商品）
honorfit_pro_lifetime_p_alex20   $15.99   （只有输入代码 ALEX20 才会出现）

光是这一个决定，就搞定了平常要靠后端做的三件事：

  • 验证代码。代码就是商品 ID。App 去问商店这个商品存不存在，存在的话，代码就是真的。
  • 折扣。就是商品的价格而已，商店会像处理其他价格一样，帮每个国家换算成当地价格。
  • 归属。Apple 和 Google 的销售报表本来就会依商品 ID 列出每一笔销售。..._p_alex20 的销售，就是 ALEX20 的销售。

除非输入代码，否则没有人看得到这些商品。App 内购买项目只要你不主动推广，就不会出现在任何一个商店的页面上，所以合作伙伴商品只对知道代码的人存在。

App 这一端

付费墙的“回复购买项目”下方多了一个小小的“有合作伙伴代码吗？”链接。点下去会出现一个文字字段。用户输入代码后，我先把它整理干净，再向商店查找那个商品。这里用的是 expo-iap，但直接用 StoreKit 或 Play Billing 也是同样的概念：

const PARTNER_PREFIX = 'honorfit_pro_lifetime_p_';

// "alex-20 " -> "ALEX20"。商品 ID 也容不下太多其他字符。
export function normalizePartnerCode(input: string) {
  const code = input.replace(/[\s-]/g, '').toUpperCase();
  return /^[A-Z0-9]{3,20}$/.test(code) ? code : null;
}

export async function lookupPartnerCode(code: string) {
  const sku = PARTNER_PREFIX + code.toLowerCase();
  const products = await fetchProducts({ skus: [sku], type: 'in-app' });
  const product = products?.find((p) => p.id === sku);
  return product ? { code, sku, price: product.displayPrice } : null;
}

如果商品有回来，终身版的卡片就会显示 19.99 美元 15.99 美元，购买按钮也会改买合作伙伴的商品，而不是一般的那个。如果没回来，字段会显示代码无效。商店错误会有自己的消息，这样手机脱机时，就不会跟人家说他手上真的代码是假的。

最后一块是权限判断。App 里所有问“这是不是 Pro 商品？”的地方，以前都是拿两个 ID 的清单来比对。现在改成检查前缀，所以购买监听器和“回复购买项目”会把合作伙伴购买当成跟终身版一模一样：

export const isProSku = (sku: string) =>
  sku === MONTHLY_SKU || sku === LIFETIME_SKU || sku.startsWith(PARTNER_PREFIX);

因为代码是向商店查找验证的，添加合作伙伴完全不需要更新 App。App 里没有一份需要随时更新的代码清单。

用 API 创建商品

每多一个合作伙伴就要在两个后台手动建一次商品，很快就会烦死，所以 bun run affiliate add ALEX20 "Alex" "alex@example.com" 会一次把两边都做好：

App Store Connect

  1. 用合作伙伴的商品 ID 创建 App 内购买项目（非消耗性）。
  2. 把终身版商品每种语言的显示名称和说明都拷贝过来。
  3. 设置 15.99 美元的美国基准价格，其他国家的价格由 Apple 自动换算。
  4. 拷贝终身版的国家／地区供应设置，上传审核用的截屏，再写一段审核备注，清楚告诉审核人员代码字段在哪里、要输入哪个代码。

接着用 bun run affiliate submit ALEX20 送交 App 审核。每个合作伙伴商品都要个别审核，通常一两天内完成。Apple 只会批准审核人员实际找得到的 App 内购买项目，所以代码字段得先出现在已上架的 App 里。

Google Play

我第一次试的是旧的 inappproducts 端点，结果回了一个 403，叫我迁移。一次性产品现在放在 oneTimeProducts 底下，一个产品可以有一个以上的购买选项。脚本会：

  1. 把终身版的商店信息和税务设置拷贝到一个新的一次性产品。
  2. 对 15.99 美元运行 pricing:convertRegionPrices，取得每个地区的价格。
  3. 用这些价格创建一个购买选项，再用 purchaseOptions:batchUpdateStates 激活它。

Play 的商品不用审核，马上就会上线。

用商店报表付钱给合作伙伴

每个月一次，bun run affiliate report 2026-11 会抓两个商店的报表，算出每个合作伙伴赚了多少：

  • Apple：App Store Connect API 的每月 Sales Summary 报表。每一列都有 SKU、数量，以及以买家币种计算的开发者收益。我用当月最后一天的汇率把收益换算成美元。Apple 是用它自己的汇率付款，所以这只是估计值，但拿来付款已经够接近了。（小陷阱：报表版本要指定 1_0。1_1 在这份报表上回了 400。）
  • Google：每月收益报表，是放在你 Play Console 的 Cloud Storage bucket 里的一个 zip。每一笔扣款、Google 手续费、税金和退款都已经是独立的列，所以依 SKU 加总就能得到真正的净收入。

每个合作伙伴拿净收入的 50%，最低为零，脚本会输出一份我可以直接拿来付款的 CSV。

Play 的小陷阱：服务账户要在 Play Console 里有“查看财务数据”权限，才能下载收益报表。我打开之后，这个账户已经可以列出文件，但下载还是回 403，大概持续了一天。如果你也遇到这种情况，先等一等，再考虑去改 bucket 权限。

取舍

  • 每个合作伙伴一个商品。只有少数几位创作者的话没问题。如果有几百位，反正你也会需要真正的基础架构。
  • Apple 的每个商品都要审核。新合作伙伴的代码在 Android 上当天就能用，在 iPhone 上则要晚一两天。
  • 代码是公开的。任何人都可以输入 ALEX20，这正是重点。计划条款禁止放上优惠券网站、禁止用自己的代码购买，退款会从之后的分成中扣除。
  • 没有点击追踪。我知道哪些代码卖出去了，但不知道谁从哪里来。对一个不追踪用户的 App 来说，我觉得这样很好。

额外提示：确认在 App 外完成的购买

这是同一周刚好遇到的事。如果有人在 Play 商店兑换 Google Play 优惠代码，购买是在你的 App 外完成的，所以你的购买监听器永远不会收到。Google 会把 3 天内没有确认（acknowledge）的购买退款。现在 HonorFit 在 Android 上，每次启动和每次回到前台时都会检查已拥有的购买，确认还没确认的那些，然后解锁 Pro。
