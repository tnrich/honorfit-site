バックエンドのない個人開発アプリでアフィリエイトコード

パートナーごとに非公開のアプリ内課金をひとつ。帳簿付けはストアがやってくれます。Thomas Willheim · 2026年11月20日

こんにちは。HonorFitは、腕立て伏せでスクリーンタイムを稼ぐ自己申告制のアプリブロッカーです。アカウントもサーバーもありません。データがスマホの中に留まるのは、ほかに行く場所がないからです。

そんなとき、あるクリエイターから「アフィリエイトプログラムはある？」と聞かれました。僕もやりたいと思いました。クリエイターはコードを受け取り、フォロワーは買い切り Proが20%オフになり、クリエイターには売上ごとに僕の取り分の50%が入る、というしくみです。ところが、調べたアフィリエイトの仕組みはどれも、コードを保存し、クリックを追跡し、購入をパートナーと結びつけるバックエンドがある前提でした。このためだけにバックエンドを作りたくはなかったし、そのために「データはスマホの外に出ない」を破るのは絶対に嫌でした。

そこで代わりにやったことを紹介します。iPhoneでもAndroidでも動き、中身はペイウォールの小さな変更と、僕のノートパソコンで動くスクリプトひとつだけです。

ストア自身のプロモーションコードを使わない理由

Appleにはオファーコードがありますが、Google Playの買い切りアイテム向けプロモーションコードは、アイテムを無料で配ることしかできません。「20%オフ」はないんです。両方のストアで同じように使えるコードをひとつにしたかったので、ストアのコードは選択肢から外れました。

それに、仮に割引ができたとしても、もうひとつ問題があります。毎月パートナーに支払うには、各売上が誰のコードから来たのかを知る必要があるんです。

コツ：パートナーごとに専用の商品を作る

HonorFitはもともと、買い切り Proを1回限りの購入honorfit_pro_lifetimeとして19.99ドルで売っています。パートナーごとにこの商品のコピーを作り、IDにそのパートナーのコードを入れて、価格を15.99ドルにします。

honorfit_pro_lifetime            $19.99   （全員に表示される商品）
honorfit_pro_lifetime_p_alex20   $15.99   （コード ALEX20 を入れたときだけ）

この決定ひとつで、普通ならバックエンドがやる3つの仕事が片付きます。

  • コードの確認。コードがそのまま商品IDです。アプリはストアに、その商品が存在するかを問い合わせます。存在すれば、そのコードは本物です。
  • 割引。ただの商品価格です。ほかの価格と同じように、ストアが国ごとに現地価格にしてくれます。
  • アトリビューション。AppleとGoogleの売上レポートには、もともとすべての売上が商品IDごとに載っています。..._p_alex20の売上は、ALEX20の売上です。

コードを入力しない限り、これらの商品は誰の目にも触れません。アプリ内課金は、自分でプロモーションしない限りどちらのストアの掲載ページにも表示されないので、パートナー商品はコードを知っている人にしか存在しないのと同じです。

アプリ側

ペイウォールの「購入を復元」の下に、小さな「パートナーコードをお持ちですか？」リンクを追加しました。タップするとテキスト入力欄が出ます。コードが入力されたら、それを整えて、ストアにその商品を問い合わせます。ここではexpo-iapを使っていますが、StoreKitやPlay Billingを直接使っても考え方は同じです。

const PARTNER_PREFIX = 'honorfit_pro_lifetime_p_';

// "alex-20 " -> "ALEX20"。商品IDにはこれ以外の文字はほとんど使えない。
export function normalizePartnerCode(input: string) {
  const code = input.replace(/[\s-]/g, '').toUpperCase();
  return /^[A-Z0-9]{3,20}$/.test(code) ? code : null;
}

export async function lookupPartnerCode(code: string) {
  const sku = PARTNER_PREFIX + code.toLowerCase();
  const products = await fetchProducts({ skus: [sku], type: 'in-app' });
  const product = products?.find((p) => p.id === sku);
  return product ? { code, sku, price: product.displayPrice } : null;
}

商品が返ってきたら、買い切りのカードに19.99ドル 15.99ドルと表示され、購入ボタンは通常の商品の代わりにパートナーの商品を購入します。返ってこなければ、入力欄にコードが無効だと表示されます。ストアのエラーには別のメッセージを出すので、オフラインのスマホが本物のコードを偽物だと言ってしまうことはありません。

最後のピースは購入資格の判定です。アプリの中で「これはPro商品？」と判定していた箇所は、以前は2つのIDのリストと比較していました。今はプレフィックスのチェックになったので、購入リスナーと「購入を復元」は、パートナー経由の購入を買い切りとまったく同じように扱います。

export const isProSku = (sku: string) =>
  sku === MONTHLY_SKU || sku === LIFETIME_SKU || sku.startsWith(PARTNER_PREFIX);

コードはストアに問い合わせて確認するので、パートナーを追加するのにアプリのアップデートは一切いりません。アプリの中に、最新に保たなければならないコードのリストはないんです。

商品をAPIで作る

パートナーが増えるたびに2つの管理画面で手作業で商品を作るのはすぐに面倒になるので、bun run affiliate add ALEX20 "Alex" "alex@example.com"で両方やるようにしました。

App Store Connect

  1. パートナーの商品IDで、アプリ内課金（非消耗型）を作成します。
  2. 買い切り商品の表示名と説明を、全言語ぶんコピーします。
  3. 米国の基準価格を15.99ドルに設定します。ほかの国の価格はAppleがそこから計算してくれます。
  4. 買い切り商品の提供国の設定をコピーし、審査用のスクリーンショットをアップロードして、コード入力欄がどこにあって、どのコードを入力すればいいのかを審査担当者にはっきり伝える審査メモを書きます。

そのあとbun run affiliate submit ALEX20でApp Reviewに提出します。パートナー商品はそれぞれ個別に審査され、たいてい1〜2日で終わります。Appleは審査担当者が実際にたどり着けるアプリ内課金しか承認しないので、先にコード入力欄が公開中のアプリに入っている必要があります。

Google Play

最初は古いinappproductsエンドポイントを使ってみたところ、移行するようにという403が返ってきました。買い切り商品は今はoneTimeProductsの下にあり、1つの商品が1つ以上の購入オプションを持ちます。スクリプトがやること：

  1. 買い切り商品の掲載情報と税設定を、新しい買い切り商品にコピーします。
  2. 15.99ドルでpricing:convertRegionPricesを実行し、全地域の価格を出します。
  3. その価格で購入オプションを1つ作り、purchaseOptions:batchUpdateStatesで有効にします。

Playの商品は審査なしで、すぐに公開されます。

ストアのレポートからパートナーに支払う

月に1回、bun run affiliate report 2026-11が両方のストアのレポートを取得して、各パートナーの取り分を計算します。

  • Apple：App Store Connect APIの月次Sales Summaryレポートです。どの行にもSKU、販売数、購入者の通貨での開発者収益が入っています。収益は月末日の為替レートで米ドルに換算します。Appleは独自のレートで支払うので、これは推定値ですが、支払いの基準にするには十分近い数字です。（ハマりどころ：レポートのバージョンは1_0を指定しましょう。1_1だと、このレポートでは400が返ってきました。）
  • Google：月次の収益レポートで、Play ConsoleのCloud Storageバケットにzipで置かれています。すべての請求、Googleの手数料、税金、払い戻しがすでに別々の行になっているので、SKUごとに合計すれば実際の純収益になります。

各パートナーには純収益の50%（下限はゼロ）が入り、スクリプトがそのまま支払いに使えるCSVを書き出します。

Playのハマりどころ：収益レポートをダウンロードするには、Play Consoleでサービスアカウントに「財務データの表示」権限が必要です。僕の場合、オンにしたあと、アカウントはファイルの一覧は取れたのに、ダウンロードは1日ほど403のままでした。同じ状態になったら、バケットの権限をいじり始める前に少し待ってみてください。

トレードオフ

  • パートナーごとに商品がひとつ。クリエイターが数人なら問題ありません。何百人にもなるなら、どのみちちゃんとしたインフラが欲しくなるはずです。
  • Appleの商品はすべて審査される。新しいパートナーのコードは、Androidではその日のうちに、iPhoneでは1〜2日後に使えるようになります。
  • コードは公開されている。誰でもALEX20と入力できますし、それが狙いです。プログラムの規約でクーポンサイトへの掲載と自分のコードでの購入は禁止していて、払い戻しはあとの支払いから差し引きます。
  • クリックの追跡はなし。わかるのはどのコードが売れたかだけで、誰がどこから来たかはわかりません。ユーザーを追跡しないアプリとしては、それで構いません。

おまけ：アプリの外でされた購入を承認する

これは同じ週に出てきた話です。誰かがGoogle PlayのプロモーションコードをPlayストアで引き換えると、購入はアプリの外で起きるので、アプリの購入リスナーはそれを受け取りません。Googleは、3日以内に承認されなかった購入を払い戻してしまいます。今のHonorFitは、Androidで起動時とフォアグラウンドに戻るたびに所有済みの購入をチェックし、まだ承認されていないものを承認して、Proを解放します。

コードが欲しい方へ

これを書いている時点で、プログラムのパートナーはゼロです。フィットネス、集中、勉強、スクリーンタイムについて発信していて、HonorFitがフォロワーに合いそうだと思ったら、パートナーページに詳細と短いフォームがあります。フォロワーは買い切りが20%オフになり、あなたには、あなたのコードで売れるたびに僕が受け取る額の半分が入ります。

HonorFit Blockerは、iPhoneとAndroid向けの無料アプリブロッカーです。腕立て伏せや好きなエクササイズでスクリーンタイムを稼げます。自己申告制で、カメラは使わず、データはスマホの外に出ません。
