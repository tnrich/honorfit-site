백엔드 없는 인디 앱의 제휴 코드

파트너마다 숨겨진 인앱 결제 상품 하나, 장부 정리는 스토어가 해 줘요. 글: Thomas Willheim · 2026년 11월 20일

안녕하세요. HonorFit은 팔굽혀펴기로 스크린 타임을 버는 자율 기록 방식의 앱 차단 앱이에요. 계정도 없고 서버도 없어요. 데이터가 폰 안에만 있는 건 달리 갈 곳이 없기 때문이에요.

그러다 한 크리에이터가 제휴 프로그램이 있냐고 물어봤어요. 저도 하고 싶었어요. 크리에이터는 코드를 받고, 팔로워는 평생 Pro를 20% 할인받고, 크리에이터는 판매마다 제가 버는 돈의 50%를 받는 거죠. 그런데 찾아본 제휴 시스템은 전부 코드를 저장하고, 클릭을 추적하고, 구매를 파트너와 연결하는 백엔드가 있다고 가정하더라고요. 이것 하나 때문에 백엔드를 만들고 싶지는 않았고, 그러려고 “폰 밖으로 아무것도 나가지 않는다”는 원칙을 깨는 건 정말 싫었어요.

그래서 대신 이렇게 했어요. iPhone과 Android 둘 다에서 동작하고, 페이월의 작은 변경과 제 노트북에서 돌리는 스크립트 하나가 전부예요.

스토어 자체 프로모션 코드는 왜 안 썼냐면

Apple에는 오퍼 코드가 있지만, Google Play의 일회성 상품용 프로모션 코드는 상품을 무료로 주는 것밖에 못 해요. “20% 할인” 같은 건 없어요. 저는 두 스토어에서 똑같이 쓸 수 있는 코드 하나를 원했기 때문에 스토어 코드는 탈락이었어요.

할인이 된다고 해도 두 번째 문제가 있어요. 매달 파트너에게 돈을 주려면 판매 하나하나가 누구의 코드에서 나왔는지 알아야 하거든요.

핵심: 파트너마다 전용 상품을 만든다

HonorFit은 원래 평생 Pro를 일회성 구매 상품 honorfit_pro_lifetime으로 19.99달러에 팔고 있어요. 파트너마다 이 상품의 복사본을 만들고, ID에 파트너의 코드를 넣고, 가격을 15.99달러로 정해요.

honorfit_pro_lifetime            $19.99   (모두에게 보이는 상품)
honorfit_pro_lifetime_p_alex20   $15.99   (코드 ALEX20을 입력했을 때만)

이 결정 하나로, 원래라면 백엔드가 하는 일 세 가지가 해결돼요.

  • 코드 확인. 코드가 곧 상품 ID예요. 앱은 스토어에 그 상품이 있는지 물어봐요. 있으면 진짜 코드예요.
  • 할인. 그냥 상품 가격이에요. 다른 가격처럼 스토어가 나라마다 현지 가격으로 바꿔 줘요.
  • 판매 귀속. Apple과 Google의 판매 보고서에는 원래 모든 판매가 상품 ID별로 나와 있어요. ..._p_alex20의 판매는 ALEX20의 판매예요.

코드를 입력하지 않으면 이 상품들은 아무에게도 보이지 않아요. 인앱 결제 상품은 직접 프로모션하지 않는 한 어느 스토어의 앱 페이지에도 나오지 않아서, 파트너 상품은 코드를 아는 사람에게만 존재하는 셈이에요.

앱 쪽

페이월의 구매 복원 아래에 작은 “파트너 코드가 있나요?” 링크를 넣었어요. 누르면 텍스트 입력란이 나와요. 코드를 입력하면 정리한 다음 스토어에 그 상품을 요청해요. 여기서는 expo-iap를 쓰지만, StoreKit이나 Play Billing을 직접 써도 아이디어는 같아요.

const PARTNER_PREFIX = 'honorfit_pro_lifetime_p_';

// "alex-20 " -> "ALEX20". 상품 ID에는 그 외의 문자를 거의 쓸 수 없다.
export function normalizePartnerCode(input: string) {
  const code = input.replace(/[\s-]/g, '').toUpperCase();
  return /^[A-Z0-9]{3,20}$/.test(code) ? code : null;
}

export async function lookupPartnerCode(code: string) {
  const sku = PARTNER_PREFIX + code.toLowerCase();
  const products = await fetchProducts({ skus: [sku], type: 'in-app' });
  const product = products?.find((p) => p.id === sku);
  return product ? { code, sku, price: product.displayPrice } : null;
}

상품이 돌아오면 평생 카드에 19.99달러 15.99달러가 표시되고, 구매 버튼은 일반 상품 대신 파트너 상품을 구매해요. 안 돌아오면 입력란에 유효하지 않은 코드라고 나와요. 스토어 오류에는 따로 메시지를 보여 줘서, 오프라인인 폰이 진짜 코드를 가짜라고 말하는 일은 없어요.

마지막 조각은 구매 권한 확인이에요. 앱에서 “이게 Pro 상품인가?”를 묻던 곳은 전부 원래 ID 두 개짜리 목록과 비교했어요. 이제는 접두사 확인이라서, 구매 리스너와 구매 복원이 파트너 구매를 평생 구매와 똑같이 취급해요.

export const isProSku = (sku: string) =>
  sku === MONTHLY_SKU || sku === LIFETIME_SKU || sku.startsWith(PARTNER_PREFIX);

코드를 스토어에 확인하기 때문에, 파트너를 추가할 때 앱 업데이트가 전혀 필요 없어요. 앱 안에 최신으로 유지해야 할 코드 목록이 없거든요.

트레이드오프

  • 파트너마다 상품 하나. 크리에이터 몇 명 정도면 괜찮아요. 수백 명이라면 어차피 제대로 된 인프라가 필요할 거예요.
  • Apple 상품은 전부 심사를 받아요. 새 파트너의 코드는 Android에서는 당일, iPhone에서는 하루이틀 뒤에 작동해요.
  • 코드는 공개돼 있어요. 누구나 ALEX20을 입력할 수 있고, 그게 핵심이에요. 프로그램 약관으로 쿠폰 사이트 게시와 자기 코드로 구매하는 걸 금지하고, 환불은 나중 정산에서 빼요.
  • 클릭 추적은 없어요. 어떤 코드가 팔렸는지는 알지만, 누가 어디서 들어왔는지는 몰라요. 사용자를 추적하지 않는 앱이니까 저는 그걸로 괜찮아요.
