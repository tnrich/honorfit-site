โค้ดพาร์ทเนอร์สำหรับแอปอินดี้ที่ไม่มีแบ็กเอนด์

การซื้อในแอปที่ซ่อนไว้หนึ่งรายการต่อพาร์ทเนอร์ แล้วให้สโตร์ทำบัญชีให้ โดย Thomas Willheim · 20 พฤศจิกายน 2026

สวัสดีทุกคน HonorFit คือแอปบล็อกแอปที่ให้คุณวิดพื้นแลกเวลาหน้าจอ ด้วยระบบเกียรติ ไม่มีบัญชีผู้ใช้และไม่มีเซิร์ฟเวอร์ ข้อมูลของคุณอยู่แค่ในมือถือ เพราะมันไม่มีที่อื่นให้ไป

แล้ววันหนึ่งก็มีครีเอเตอร์คนหนึ่งถามว่าเรามีโปรแกรม affiliate ไหม เราก็อยากมี: ครีเอเตอร์ได้โค้ด ผู้ติดตามของเขาได้ส่วนลด 20% สำหรับ Pro ตลอดชีพ และครีเอเตอร์ได้50% ของเงินที่เราได้จากทุกยอดขาย แต่ระบบ affiliate ทุกแบบที่เราดูมาล้วนสมมติว่ามีแบ็กเอนด์ไว้เก็บโค้ด ติดตามคลิก และจับคู่การซื้อกับพาร์ทเนอร์ เราไม่อยากสร้างแบ็กเอนด์ขึ้นมาแค่เพื่อเรื่องนี้ และยิ่งไม่อยากทำลายหลัก “ไม่มีอะไรออกจากมือถือของคุณ” เพื่อทำสิ่งนี้

นี่คือสิ่งที่เราทำแทน ใช้ได้ทั้งบน iPhone และ Android และมีแค่การแก้หน้า paywall นิดหน่อย กับสคริปต์ตัวเดียวที่รันบนโน้ตบุ๊กของเรา

ทำไมไม่ใช้โค้ดโปรโมชันของสโตร์เอง?

Apple มี offer code แต่โค้ดโปรโมชันของ Google Play สำหรับสินค้าแบบซื้อครั้งเดียวทำได้แค่แจกสินค้าฟรีเท่านั้น ไม่มีแบบ “ลด 20%” เราอยากได้โค้ดเดียวที่ใช้ได้เหมือนกันทั้งสองสโตร์ โค้ดของสโตร์จึงตกไป

และต่อให้ลดราคาได้ ก็ยังมีปัญหาที่สอง: ทุกเดือนเราต้องรู้ว่ายอดขายแต่ละรายการมาจากโค้ดของใคร ถึงจะจ่ายเงินให้แต่ละคนได้

เคล็ดลับ: พาร์ทเนอร์ทุกคนได้สินค้าของตัวเอง

HonorFit ขาย Pro ตลอดชีพเป็นการซื้อครั้งเดียวอยู่แล้ว คือ honorfit_pro_lifetime ราคา 19.99 ดอลลาร์ พาร์ทเนอร์แต่ละคนจะได้สำเนาของสินค้านี้ที่มีโค้ดของตัวเองอยู่ใน ID และตั้งราคาไว้ที่ 15.99 ดอลลาร์:

honorfit_pro_lifetime            $19.99   (สินค้าที่ทุกคนเห็น)
honorfit_pro_lifetime_p_alex20   $15.99   (เฉพาะเมื่อใส่โค้ด ALEX20)

การตัดสินใจข้อเดียวนี้จัดการงานสามอย่างที่ปกติแบ็กเอนด์ต้องทำ:

  • ตรวจโค้ด โค้ดก็คือ product ID แอปถามสโตร์ว่ามีสินค้านั้นอยู่ไหม ถ้ามี โค้ดนั้นก็ของจริง
  • ส่วนลด ก็แค่ราคาของสินค้า ซึ่งสโตร์แปลงเป็นราคาท้องถิ่นให้ทุกประเทศเหมือนราคาอื่นๆ
  • การระบุที่มาของยอดขาย รายงานยอดขายของ Apple และ Google แสดงทุกยอดขายแยกตาม product ID อยู่แล้ว ยอดขายของ ..._p_alex20 ก็คือยอดขายของ ALEX20

ไม่มีใครเห็นสินค้าเหล่านี้ถ้าไม่ได้พิมพ์โค้ด การซื้อในแอปจะไม่แสดงในหน้าแอปของสโตร์ไหนเลย เว้นแต่คุณเลือกจะโปรโมต สินค้าของพาร์ทเนอร์จึงมีอยู่สำหรับคนที่รู้โค้ดเท่านั้น

ฝั่งแอป

หน้า paywall มีลิงก์เล็กๆ “มีโค้ดพาร์ทเนอร์ไหม?” เพิ่มเข้ามาใต้ปุ่มกู้คืนการซื้อ แตะแล้วจะมีช่องให้พิมพ์ข้อความ เมื่อมีคนใส่โค้ด เราจะจัดรูปแบบให้เรียบร้อยแล้วขอสินค้านั้นจากสโตร์ ตรงนี้ใช้ expo-iap แต่ถ้าใช้ StoreKit หรือ Play Billing ตรงๆ ก็เป็นแนวคิดเดียวกัน:

const PARTNER_PREFIX = 'honorfit_pro_lifetime_p_';

// "alex-20 " -> "ALEX20" เพราะ product ID ใส่ตัวอักษรอื่นได้ไม่มาก
export function normalizePartnerCode(input: string) {
  const code = input.replace(/[\s-]/g, '').toUpperCase();
  return /^[A-Z0-9]{3,20}$/.test(code) ? code : null;
}

export async function lookupPartnerCode(code: string) {
  const sku = PARTNER_PREFIX + code.toLowerCase();
  const products = await fetchProducts({ skus: [sku], type: 'in-app' });
  const product = products?.find((p) => p.id === sku);
  return product ? { code, sku, price: product.displayPrice } : null;
}

ถ้าสินค้าส่งกลับมา การ์ด Pro ตลอดชีพจะแสดง 19.99 ดอลลาร์ 15.99 ดอลลาร์ และปุ่มซื้อจะซื้อสินค้าของพาร์ทเนอร์แทนสินค้าปกติ ถ้าไม่มี ช่องจะบอกว่าโค้ดไม่ถูกต้อง ข้อผิดพลาดจากสโตร์มีข้อความแยกของมันเอง มือถือที่ออฟไลน์อยู่จึงไม่บอกใครว่าโค้ดจริงของเขาเป็นโค้ดปลอม

ชิ้นสุดท้ายคือสิทธิ์การใช้งาน ทุกจุดในแอปที่เคยถามว่า “นี่เป็นสินค้า Pro ไหม?” เดิมเทียบกับรายการ ID สองตัว ตอนนี้เปลี่ยนเป็นเช็ก prefix แทน ตัวรับฟังการซื้อและปุ่มกู้คืนการซื้อจึงถือว่าการซื้อผ่านพาร์ทเนอร์เหมือนกับ Pro ตลอดชีพทุกประการ:

export const isProSku = (sku: string) =>
  sku === MONTHLY_SKU || sku === LIFETIME_SKU || sku.startsWith(PARTNER_PREFIX);

เพราะโค้ดถูกตรวจกับสโตร์ การเพิ่มพาร์ทเนอร์จึงไม่ต้องอัปเดตแอปเลย ในแอปไม่มีรายการโค้ดที่ต้องคอยอัปเดตให้ทันสมัย

App Store Connect

  1. สร้างการซื้อในแอป (แบบ non-consumable) ด้วย product ID ของพาร์ทเนอร์
  2. คัดลอกชื่อที่แสดงและคำอธิบายของสินค้า Pro ตลอดชีพในทุกภาษา
  3. ตั้งราคาฐานในสหรัฐฯ ไว้ที่ 15.99 ดอลลาร์ แล้ว Apple จะคำนวณราคาของประเทศอื่นๆ ให้
  4. คัดลอกประเทศที่เปิดขายของ Pro ตลอดชีพ อัปโหลดภาพหน้าจอสำหรับการรีวิว และเขียนหมายเหตุถึงผู้รีวิวที่บอกชัดๆ ว่าช่องใส่โค้ดอยู่ตรงไหนและต้องพิมพ์โค้ดอะไร

Google Play

รอบแรกเราลองใช้ endpoint เก่า inappproducts ซึ่งตอบกลับมาเป็น 403 บอกให้ย้ายไปใช้ของใหม่ ตอนนี้สินค้าแบบซื้อครั้งเดียวอยู่ใต้ oneTimeProducts ซึ่งสินค้าหนึ่งตัวมีตัวเลือกการซื้อได้ตั้งแต่หนึ่งแบบขึ้นไป สคริปต์จะ:

  1. คัดลอกข้อมูลหน้าร้านและการตั้งค่าภาษีของ Pro ตลอดชีพไปยังสินค้าแบบซื้อครั้งเดียวตัวใหม่
  2. รัน pricing:convertRegionPrices กับราคา 15.99 ดอลลาร์ เพื่อได้ราคาของทุกภูมิภาค
  3. สร้างตัวเลือกการซื้อแบบ buy หนึ่งแบบด้วยราคาเหล่านั้น แล้วเปิดใช้งานด้วย purchaseOptions:batchUpdateStates

จ่ายเงินพาร์ทเนอร์จากรายงานของสโตร์

เดือนละครั้ง bun run affiliate report 2026-11 จะดึงรายงานจากทั้งสองสโตร์ แล้วคำนวณว่าพาร์ทเนอร์แต่ละคนได้เท่าไหร่:

  • Apple: รายงาน Sales Summary รายเดือนจาก App Store Connect API ทุกแถวมี SKU จำนวน และรายได้ของนักพัฒนาในสกุลเงินของผู้ซื้อ เราแปลงรายได้เป็นดอลลาร์สหรัฐด้วยอัตราแลกเปลี่ยนของวันสุดท้ายของเดือน Apple จ่ายเงินด้วยอัตราของตัวเอง ตัวเลขนี้จึงเป็นค่าประมาณ แต่ใกล้พอที่จะใช้จ่ายเงินได้ (ข้อควรระวัง: ขอรายงานเวอร์ชัน 1_0 เพราะ 1_1 ตอบกลับมาเป็น 400 สำหรับรายงานนี้)
  • Google: รายงานรายได้รายเดือน เป็นไฟล์ zip ใน Cloud Storage bucket ของ Play Console คุณ ในนั้นมีทุกการเรียกเก็บเงิน ค่าธรรมเนียมของ Google ภาษี และการคืนเงินแยกเป็นแถวไว้อยู่แล้ว รวมยอดตาม SKU ก็ได้รายได้สุทธิจริง

พาร์ทเนอร์แต่ละคนได้ 50% ของรายได้สุทธิ โดยต่ำสุดคือศูนย์ และสคริปต์จะเขียนไฟล์ CSV ที่เราใช้จ่ายเงินได้เลย

ข้อควรระวังของ Play: บัญชีบริการต้องมีสิทธิ์ “ดูข้อมูลทางการเงิน” ใน Play Console ถึงจะดาวน์โหลดรายงานรายได้ได้ หลังจากเราเปิดสิทธิ์นี้ บัญชีแสดงรายการไฟล์ได้แล้ว แต่ดาวน์โหลดยังได้ 403 อยู่ประมาณหนึ่งวัน ถ้าของคุณเป็นแบบนั้น ให้รอก่อนจะเริ่มไปแก้สิทธิ์ของ bucket

ข้อแลกเปลี่ยน

  • สินค้าหนึ่งตัวต่อพาร์ทเนอร์หนึ่งคน ถ้ามีครีเอเตอร์ไม่กี่คนก็ไม่มีปัญหา ถ้ามีเป็นร้อยคน ยังไงคุณก็ต้องมีโครงสร้างพื้นฐานจริงจังอยู่ดี
  • สินค้าของ Apple ทุกตัวต้องผ่านการรีวิว โค้ดของพาร์ทเนอร์ใหม่ใช้บน Android ได้ในวันเดียวกัน และบน iPhone ได้ในอีกหนึ่งหรือสองวันต่อมา
  • โค้ดเป็นสาธารณะ ใครก็พิมพ์ ALEX20 ได้ และนั่นคือจุดประสงค์ เงื่อนไขของโปรแกรมห้ามลงในเว็บคูปองและห้ามซื้อด้วยโค้ดของตัวเอง และการคืนเงินจะหักจากการจ่ายเงินครั้งต่อๆ ไป
  • ไม่มีการติดตามคลิก เรารู้ว่าโค้ดไหนขายได้ แต่ไม่รู้ว่าใครเข้ามาจากไหน สำหรับแอปที่ไม่ติดตามผู้ใช้ เราโอเคกับแบบนี้

แถม: ยืนยันการซื้อที่เกิดขึ้นนอกแอป
